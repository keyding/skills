# Emil Kowalski 的 Skills

[全部 Skill 指南](README_zh-CN.md) · [English](emilkowalski.md)

## `animate`

**Skill 介绍：** 从基本原则出发设计并实现 Web 动画，先判断是否应该有动画，再决定目的、工具、属性、时序、打断行为和无障碍降级。

**具体使用场景与方法：** 在 Web 界面中添加过渡、手势、进入、退出或其他动效时使用。调用 `/animate` 并提供组件和期望行为。它会使用能满足需求的最低成本技术直接实现，也可能拒绝没有必要的动画，并同时处理减少动态效果和指针能力差异。

## `animate-expo`

**Skill 介绍：** 使用 Reanimated、Gesture Handler、Expo Router，并在合适时结合触觉反馈，为 React Native 和 Expo 构建生产级动画与手势。

**具体使用场景与方法：** 适合移动端手势、Sheet、页面转场、按压反馈、触觉反馈，或真机上卡顿的动画。调用 `/animate-expo` 并说明交互和目标组件。它会把逐帧工作保留在 UI 线程，并要求在真实设备的 Release 构建上验证手感和性能。

## `animation-vocabulary`

**Skill 介绍：** 把对可见动效的模糊描述转换为准确的动画术语；描述有歧义时还会给出相近术语及区别。

**具体使用场景与方法：** 当你能描述动画看起来或感觉如何，却不知道它叫什么时使用。调用 `/animation-vocabulary` 并附上描述，例如：`/animation-vocabulary iOS 滚动到边界后产生阻力并弹回的效果叫什么？` 它只负责命名，不负责设计或实现。

## `apple-design`

**Skill 介绍：** 将 Apple 的流畅、物理化界面原则应用到 Web，涵盖即时反馈、直接操控、可打断弹簧、速度衔接、动量、材质、排版和无障碍。

**具体使用场景与方法：** 在构建或审查 Apple 风格手势、拖拽界面、Sheet、弹簧动效、半透明层次或排版时使用。调用 `/apple-design` 并提供要讨论的交互或设计。特别适合在实施前或实施中推敲行为和手感，尤其是动效需要持续跟随用户输入的场景。

## `ask-sonner`

**Skill 介绍：** 提供 React Toast 库 Sonner 的实施和排障指导，包括安装、调用选择、Promise 流程、更新、样式、主题、位置和多个 Toaster。

**具体使用场景与方法：** 在添加、定制或调试 Sonner 时使用。调用 `/ask-sonner` 并说明期望行为或症状，例如重复 Toast、样式丢失、暗色模式异常、层叠问题或 Promise Toast 卡住。它会选择正确 API，并只在需要时从默认样式逐步升级到无头自定义组件。

## `emil-design-eng`

**Skill 介绍：** 汇集 Emil Kowalski 更广泛的设计工程理念，覆盖精致组件、目的明确的动效、物理交互、性能、无障碍，以及让界面形成一致体验的细节。

**具体使用场景与方法：** 当你构建或审查交互式 UI，问题跨越多个专项动效领域时，把它作为通用工艺框架使用。调用 `/emil-design-eng` 并提供组件、实现或设计问题。范围更窄时，优先使用 `animate`、`review-animations`、`find-animation-opportunities` 或 `ask-sonner`。

## `emil-prototype`

**Skill 介绍：** 为一个 UI 元素构建多个真正不同的版本，并通过可视化选择器实时比较，最后把选中版本提升到正式实现。

**具体使用场景与方法：** 当组件的视觉方向或交互方式尚不确定，而直接看方案比口头讨论更高效时使用。调用 `/emil-prototype <描述>`；追加 `x5` 可生成五个版本，使用 `riff <版本>` 深挖某个方向，使用 `keep <版本>` 将选中方案应用到产品。

## `find-animation-opportunities`

**Skill 介绍：** 以只读方式扫描真正能从动效中获益的位置，并明确拒绝应该保持静态的候选项。

**具体使用场景与方法：** 当界面显得平淡，希望得到克制的动画建议，而不是直接实施时使用。调用 `/find-animation-opportunities` 并提供页面、组件或仓库范围。它只返回少量有证据且带精确参数的建议，同时列出因频率、目的、速度或功能门槛而被拒绝的候选项。

## `improve-animations`

**Skill 介绍：** 审计整个代码库的现有动效，排列已验证问题的优先级，并编写独立完整的实施计划，不直接修改源代码。

**具体使用场景与方法：** 当你需要动效改进路线图，而不是只审查一个 Diff 时使用。调用 `/improve-animations`，可追加 `quick`、`deep`、`performance` 等分类，或使用 `plan <描述>`。查看审计结果后选择要生成计划的项目；之后还可用 `execute <计划>` 交给隔离的实施流程。

## `mobile-native`

**Skill 介绍：** 通过修复触摸、视口、安全区域、键盘、滚动回弹、状态栏、轮播、选择行为和真机差异，让移动 Web 应用或 PWA 更像原生应用。

**具体使用场景与方法：** 当界面在桌面浏览器可用，但在手机上手感不对，或正在开发全屏移动 Web 体验时使用。调用 `/mobile-native` 并提供受影响页面和症状。它会应用有针对性的 CSS 和元数据修复，并明确区分哪些可通过代码验证，哪些必须在真实设备上确认。

## `pick-ui-library`

**Skill 介绍：** 根据当前项目技术栈，从 Emil 的精选清单中为某个前端需求推荐一个合适的 UI 库。

**具体使用场景与方法：** 在为 Toast、OTP 输入、命令菜单、动画、图表、拖拽、虚拟列表、状态管理或样式处理等需求新增依赖前使用。调用 `/pick-ui-library` 并说明需求和限制。它会先检查现有依赖，除非你明确要求，否则不会替换已有的同类方案。

## `review-animations`

**Skill 介绍：** 按照 Emil Kowalski 的设计工程标准审查动画和动效代码，输出动效专项问题和结论。

**具体使用场景与方法：** 在实现或修改过渡、手势、加载动画、布局动画等动效后使用。调用 `/review-animations` 并提供相关文件、Diff 或组件。它会检查目的、频率、时长、缓动、可打断性、性能、变换原点、减少动态效果支持和视觉一致性；非动效问题应另用通用代码审查 Skill。

## `write-swift`

**Skill 介绍：** 指导现代 Swift 的编写与审查，涵盖值建模、Swift 6 并发、协议与泛型、API 设计、性能、ARC、Swift Testing、宏、诊断和迁移。

**具体使用场景与方法：** 在编写或审查 Swift、迁移到 Swift 6，或诊断数据竞争、卡死、引用循环和性能问题时使用。调用 `/write-swift` 并提供代码或问题，同时说明项目 Swift 版本。它默认从简单、值导向、单线程设计开始，只有存在明确原因时才引入并发、引用语义、存在类型或不安全 API。
