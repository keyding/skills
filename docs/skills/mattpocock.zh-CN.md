# Matt Pocock 的 Skills

[全部 Skill 指南](README_zh-CN.md) · [English](mattpocock.md)

## `ask-matt`

**Skill 介绍：** 根据当前目标，从本集合的 Matt Pocock Skills 中选择最适合的单个 Skill 或组合流程。

**具体使用场景与方法：** 当你知道想要什么结果，却不确定该用哪个 Skill，或怀疑任务需要多个 Skill 串联时使用。调用 `/ask-matt` 并说明目标和当前上下文，例如：`/ask-matt 我有一个模糊的功能想法，想把它变成可实施的任务。`

## `claude-handoff`

**Skill 介绍：** 总结当前对话，并立即启动一个新的 Claude 后台 Agent 继续工作。

**具体使用场景与方法：** 当当前对话上下文过长、希望新 Agent 在干净上下文中接手，或希望后台继续处理时使用。调用 `/claude-handoff`，也可以指定新 Agent 应聚焦的工作。该 Skill 需要本机已安装并登录 Claude CLI，交接内容会排除密钥。

## `code-review`

**Skill 介绍：** 从两个独立维度审查分支或变更集：是否符合仓库的工程规范，以及是否忠实实现原始规格。

**具体使用场景与方法：** 在合并分支前、审查 PR 时，或检查某个 commit、tag、分支之后的工作时使用。调用 `/code-review <固定点>`，例如 `/code-review main`；如果无法从提交或 Issue 找到规格，还应提供规格来源。两个审查维度会保持分离，因此既能发现“代码合规但做错需求”，也能发现“满足需求但违反规范”。

## `codebase-design`

**Skill 介绍：** 提供设计深模块的共享词汇和方法，以小接口、清晰接缝、高杠杆和高局部性组织代码。

**具体使用场景与方法：** 在设计或重构模块、确定测试接缝、减少浅层转发代码，或比较不同接口方案时使用。调用 `/codebase-design` 并提供模块或设计问题；特别适合在重构前或定义可测试的公共接口时使用。

## `diagnosing-bugs`

**Skill 介绍：** 对困难 Bug 和性能回归执行严格诊断循环：建立紧密复现、最小化、排列假设、插桩、修复并保留回归测试。

**具体使用场景与方法：** 当故障间歇出现、原因不明、与性能相关，或简单修复已经失败时使用。调用 `/diagnosing-bugs` 并提供症状和已有复现信息。Skill 会先建立一个快速、确定、能捕捉准确症状的命令，再开始提出理论或修改代码。

## `domain-modeling`

**Skill 介绍：** 通过澄清模糊术语、验证边界场景、更新 `CONTEXT.md`，并仅将稳定架构决策记录为 ADR，持续完善项目领域语言。

**具体使用场景与方法：** 当团队术语冲突、领域关系不清，或设计讨论改变项目概念模型时使用。调用 `/domain-modeling` 并提供主题或争议术语。它会把说法与代码互相核对，并在决策稳定时写入词汇表或 ADR。

## `git-guardrails-claude-code`

**Skill 介绍：** 为 Claude Code 安装 Hook，阻止 push、hard reset、强制 clean、破坏性删除分支和恢复整个工作树等危险 Git 命令。

**具体使用场景与方法：** 当你希望为单个项目或全局环境增加防误操作保护时使用。调用 `/git-guardrails-claude-code`，选择安装范围，并可自定义禁止的命令。Skill 会把 Hook 合并到现有配置，并验证危险命令确实被拒绝。

## `grill-me`

**Skill 介绍：** 通过持续追问和挑战假设，把模糊的计划、设计或决策打磨清楚。

**具体使用场景与方法：** 适合早期想法、架构选择、产品计划或任何需要压力测试、但不需要写入仓库文档的方案。调用 `/grill-me` 并附上要审视的想法或决定，然后逐轮回答问题。

## `grill-with-docs`

**Skill 介绍：** 在执行与 `grill-me` 相同的深入访谈时，将稳定的领域词汇和架构决策同步记录到仓库。

**具体使用场景与方法：** 当讨论属于一个真实代码库，而且结论需要在会话结束后继续保留时使用。调用 `/grill-with-docs` 并说明拟议变更；随着决策形成，它会更新领域上下文和 ADR 类文档。

## `grilling`

**Skill 介绍：** 将计划、决策或想法组织成分支设计树，按轮次提出当前所有可回答的问题，对方案进行压力测试。

**具体使用场景与方法：** 当你想直接使用访谈方法，而不需要 `grill-me` 或 `grill-with-docs` 的包装行为时使用。调用 `/grilling` 并提供方案。Agent 会自行查找可查证事实，为每个问题提供建议答案，并在实施前停下，让你确认双方已经形成共同理解。

## `handoff`

**Skill 介绍：** 把当前对话压缩为便于携带的 Markdown 交接文档，但不会自动启动另一个 Agent。

**具体使用场景与方法：** 当你准备换一个会话、Agent 工具或交给同事继续时使用。调用 `/handoff`，可选填下一步任务或接收者。Skill 会在临时目录写入文档、引用已有产物并排除密钥。

## `implement-spec`

**Skill 介绍：** 实施完整的规格或任务依赖图，协调并行开发、集成、审查和 Pull Request 准备工作。

**具体使用场景与方法：** 当已有完整且获准实施的规格，希望在一个分支或 PR 中交付全部工作时使用。调用 `/implement-spec` 并提供规格、Issue 或任务图引用。它适合完整实施；只做一个有限任务时应使用 `implement`。

## `implement`

**Skill 介绍：** 实施规格或任务集中的一个有限工作项，完成验证、审查，并提交到当前分支。

**具体使用场景与方法：** 适合单个 Ticket，或能在一次工作会话中完成的小型垂直切片。调用 `/implement` 并提供 Ticket、规格章节或验收标准。它会在约定的测试边界上编写测试，并完成类型检查、测试、代码审查和提交。

## `improve-codebase-architecture`

**Skill 介绍：** 审查代码库中可以形成更深、更清晰模块的机会，生成可视化 HTML 报告，并继续讨论选中的改进项。

**具体使用场景与方法：** 当代码能够运行，但模块过浅、耦合严重、重复较多或难以导航时使用。在仓库根目录调用 `/improve-codebase-architecture`，查看生成的报告，选择一个候选方案，再通过引导式讨论明确实施方向。

## `loop-me`

**Skill 介绍：** 通过有状态访谈，把重复发生的个人或工作流程整理为可构建的工作流规格。

**具体使用场景与方法：** 适合周报、内容发布、支持工单分流、发布流程等以后可能自动化的重复工作。调用 `/loop-me` 并描述例行流程和期望结果。Skill 会在工作区文档中记录触发条件、检查点、必须由人完成的步骤和可复用 Brief。

## `matt-prototype`

**Skill 介绍：** 为回答一个设计问题构建明确会被丢弃的代码，根据问题选择交互式逻辑／状态演示，或多个 UI 方案。

**具体使用场景与方法：** 当纯讨论无法确定状态模型如何运作，或界面应该长什么样时使用。调用 `/matt-prototype` 并给出要回答的准确问题。原型应容易运行、完整展示状态、不做生产级打磨；验证后的决定进入正式代码，原型本身则保存在主分支之外作为决策证据。

## `migrate-to-shoehorn`

**Skill 介绍：** 将测试中的不安全 TypeScript 类型断言迁移到 `@total-typescript/shoehorn`，用局部或故意无效的数据构造测试夹具。

**具体使用场景与方法：** 当测试因完整对象太大而使用 `as Type`，或为测试错误路径使用 `as unknown as Type` 时使用。调用 `/migrate-to-shoehorn` 并提供测试文件或范围。它会安装依赖，在 `fromPartial`、`fromAny` 和 `fromExact` 中选择合适方法，并通过类型检查验证迁移。

## `pr`

**Skill 介绍：** 编写简洁的 PR 描述，包含可视化摘要、具体的前后证据，以及可逆性和影响范围评估。

**具体使用场景与方法：** 在实现和验证完成后，需要向审查者清楚解释改动时使用。调用 `/pr` 并提供 Diff 或分支上下文。Skill 会选择最小且有效的图、树、伪代码或 Diff 草图，并只用实际结果填写 Evidence，避免无依据的结论。

## `research`

**Skill 介绍：** 将聚焦的调查任务交给后台 Agent，要求使用高可信的一手来源，并把带引用的结论写入仓库中的单个 Markdown 文件。

**具体使用场景与方法：** 当设计或实施决策依赖官方文档、规范、源代码或第一方 API，并希望调研与其他工作并行时使用。调用 `/research` 并提供准确问题；有需要时同时指定输出位置。

## `resolving-merge-conflicts`

**Skill 介绍：** 通过恢复冲突双方的原始意图来解决进行中的 merge 或 rebase，合并兼容改动、验证结果并完成 Git 操作。

**具体使用场景与方法：** 仅在仓库已经处于 merge 或 rebase 冲突状态时使用。调用 `/resolving-merge-conflicts`；如果合并目标不明显，还应说明目标。Skill 会把 commit、PR 和 Issue 作为主要证据，尽量保留双方意图，运行项目检查，并继续完成操作而不是中止。

## `retro`

**Skill 介绍：** 对一次编码会话进行复盘，并给出改善 Agent 工作环境和工程闭环的具体建议。

**具体使用场景与方法：** 在一次耗时、困难、重复操作多或频繁失败的会话后使用。调用 `/retro` 复盘当前会话，也可以指定其他会话。它会寻找更好的导航、确定性检查、仓库说明、工具配置以及减少无效工作的方式。

## `scaffold-exercises`

**Skill 介绍：** 创建正确编号的课程练习目录，包含 problem、solution 或 explainer 变体，以及通过 AI Hero 练习 Lint 所需的最少文件。

**具体使用场景与方法：** 在新建课程章节、把课程计划转换为练习骨架，或重新编号已有练习时使用。调用 `/scaffold-exercises` 并提供章节计划和所需变体。它会创建结构、运行 `pnpm ai-hero-cli internal lint`、修复错误并提交通过验证的骨架。

## `setup-matt-pocock-skills`

**Skill 介绍：** 为 Matt 的工程类 Skills 完成一次性仓库配置，包括 Issue Tracker 约定、分流状态和领域文档布局。

**具体使用场景与方法：** 在新仓库首次使用 `triage`、`to-spec`、`to-tickets` 或 `wayfinder` 等 Skill 前运行。在仓库根目录调用 `/setup-matt-pocock-skills`，审查它提出的 Tracker 和文档约定，确认后再创建文件或标签。

## `setup-pre-commit`

**Skill 介绍：** 接入 Husky 和 lint-staged，在每次提交前格式化暂存文件，并运行仓库已有的类型检查和测试。

**具体使用场景与方法：** 当 JavaScript 或 TypeScript 仓库需要统一的提交前检查时使用。在仓库根目录调用 `/setup-pre-commit`。它会检测包管理器、保留已有 Prettier 配置、跳过不存在的脚本、验证 Hook，并创建一次冒烟测试提交。

## `setup-ts-deep-modules`

**Skill 介绍：** 在 TypeScript 仓库中配置 `dependency-cruiser`，让每个包只暴露小型公共入口，并隐藏内部实现。

**具体使用场景与方法：** 当项目存在跨包直接导入内部文件、依赖边界不清或循环依赖时使用。在仓库根目录调用 `/setup-ts-deep-modules`。它会安装并接入检查规则、添加示例约束、演示一次违规失败，再验证修复后的配置。

## `tdd`

**Skill 介绍：** 通过小型红绿垂直切片推进实施，从约定的公共接缝测试行为，而不是测试内部实现。

**具体使用场景与方法：** 在测试优先地开发功能或修复 Bug，尤其需要集成层信心时使用。调用 `/tdd` 并说明目标行为，在编写任何测试前先确认测试接缝。每轮只增加一个失败测试和让它通过所需的最少实现，重构留到审查阶段。

## `teach`

**Skill 介绍：** 创建可跨多次会话持续使用的学习工作区，通过课程、练习、可信资料和进度记录教授一个主题。

**具体使用场景与方法：** 当你想长期掌握一项能力，而不是只听一次解释时使用。调用 `/teach` 并说明主题、当前水平和目标能力，例如：`/teach 帮我熟练掌握 Rust 所有权。` 后续课程会根据已记录的学习进度调整。

## `to-questionnaire`

**Skill 介绍：** 把你无法独自完成的决策，转化为一份面向掌握缺失信息之人的重点问卷。

**具体使用场景与方法：** 适合利益相关者访谈、供应商沟通、领域专家评审或异步需求调研。调用 `/to-questionnaire` 并说明要做的决定和接收者。Skill 只会询问接收者情况和你需要获得的答案，然后生成 `to-questionnaire-<slug>.md`。

## `to-spec`

**Skill 介绍：** 将当前对话和代码库上下文整理为完整规格，并发布到已配置的 Issue Tracker。

**具体使用场景与方法：** 在需求和主要决策已经讨论清楚后使用。调用 `/to-spec`，通常不会再进行需求访谈；如果上下文在别处，再补充引用。它会确认测试边界、编写规格并标记为可由 Agent 接手。新仓库应先运行 `setup-matt-pocock-skills`。

## `to-tickets`

**Skill 介绍：** 将计划或规格拆成小型、端到端的示踪弹式 Ticket，并明确每个 Ticket 的阻塞关系。

**具体使用场景与方法：** 当一份规格大到无法在单次会话中完成，需要拆成可独立交付的工作项时使用。调用 `/to-tickets` 并提供规格路径、Issue URL，或直接使用当前对话作为来源。在 Skill 发布 Ticket 前，先审查并确认任务粒度和依赖关系。

## `triage`

**Skill 介绍：** 按既定状态机分流 Issue 和符合条件的外部 PR，包括验证、补充信息、拒绝以及编写 Agent 可执行的 Brief。

**具体使用场景与方法：** 用于查找未分流工作、检查指定 Issue 或 PR，或改变条目状态。例如：`/triage 列出需要我处理的内容`、`/triage 把 #42 移到 ready-for-agent`。它可能修改标签、发表评论或关闭条目，因此执行前应确认它的建议和状态变更。

## `wait-what`

**Skill 介绍：** 中止当前解释，要求 Agent 补充上下文，使用更简单的英语和仓库中已经确立的领域语言重新说明。

**具体使用场景与方法：** 当上一条回复默认了过多背景、使用了未解释的术语，或你已经跟不上讨论时使用。在令人困惑的回复后立即调用 `/wait-what`，也可以指出具体没听懂的部分。

## `wayfinder`

**Skill 介绍：** 把超出单个 Agent 会话容量、路线尚不清晰的大型工作规划成共享的决策 Ticket 地图，再逐个解决决策。

**具体使用场景与方法：** 适合大型迁移、模糊的产品计划，或其他已经知道终点但不知道路径的工作。调用 `/wayfinder` 并提供模糊想法来创建地图；也可以带上已有地图的 URL 或编号来处理下一个决策。默认只做规划，且每个会话通常只解决一个非研究类 Ticket。

## `wizard`

**Skill 介绍：** 为只有人才能完成的手动步骤生成交互式 Bash 向导，例如注册账户、复制凭据、配置控制台或批准切换。

**具体使用场景与方法：** 当可重复流程涉及人类专用网页界面或密钥输入，否则需要与 Agent 反复来回沟通时使用。调用 `/wizard` 并提供目标结果。确认步骤顺序和每个值的写入位置后，它会生成并静态验证可执行脚本；最终由你亲自运行脚本。

## `writing-beats`

**Skill 介绍：** 从固定的原始素材中逐个构建文章的叙事节拍，并确保任何概念在后文依赖前已经向读者解释清楚。

**具体使用场景与方法：** 当探索已经结束，但你希望在故事或论证层面逐步选择文章路径时使用。调用 `/writing-beats` 并提供原始素材文件和输出路径。每轮从候选开头或下一节拍中选择一个，Skill 只追加选中的内容并保留你的编辑。

## `writing-fragments`

**Skill 介绍：** 通过访谈探索写作主题，持续捕捉有价值的句子、观点、例子、比喻和半成品想法，但不强加大纲。

**具体使用场景与方法：** 适合文章或随笔最初阶段，用来发现自己真正想表达什么。调用 `/writing-fragments` 并提供主题和目标 Markdown 文件。继续对话即可让 Skill 追加片段，之后再用 `writing-beats` 或 `writing-shape` 组织素材。

## `writing-for-agents`

**Skill 介绍：** 提供编写可靠 Skill、`AGENTS.md`、`CLAUDE.md` 和其他 Agent 消费文档的原则，关注上下文指针、渐进披露、完成条件和维护成本。

**具体使用场景与方法：** 当你创建或修改 AI Agent 指令，希望行为稳定且避免常驻上下文膨胀时使用。调用 `/writing-for-agents` 并提供目标文档和期望行为。它会帮助判断哪些内容应内联、哪些应通过链接披露、触发条件如何表达，以及每个步骤如何证明完成。

## `writing-shape`

**Skill 介绍：** 交互式地把固定的原始素材文件整理成文章，先选择开头，再按顺序塑造每个段落或内容块。

**具体使用场景与方法：** 当探索完成，希望直接控制文章的论点、结构、过渡和呈现形式时使用。调用 `/writing-shape` 并提供素材文件和输出路径。源文件保持只读，文章会按照每轮确认的内容逐块增长。
